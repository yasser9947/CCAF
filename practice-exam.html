  1. 1.عرّف 3–4 أدوات MCP بأوصاف مفصّلة تفرّق بوضوح غرض كل أداة ومدخلاتها وحدودها. ضمّن أداتين متشابهتين وظيفياً تحتاجان وصفاً دقيقاً لتفادي الالتباس.Define 3–4 MCP tools with detailed descriptions that clearly differentiate each tool's purpose, inputs, and boundaries. Include two functionally similar tools that require careful wording to avoid selection confusion.
  2. 2.نفّذ حلقة وكيلية تفحص stop_reason لتقرر هل تواصل تنفيذ الأدوات أو تقدّم الرد النهائي. عالج "tool_use" و"end_turn" صح.Implement an agentic loop that checks stop_reason to decide whether to continue executing tools or present the final response. Handle both "tool_use" and "end_turn" correctly.
  3. 3.أضف ردود أخطاء مهيكلة: errorCategory (transient/validation/permission)، وisRetryable boolean، ووصفاً بشرياً. اختبر أن الوكيل يعالج كل نوع صح (إعادة المؤقت، شرح أخطاء العمل للمستخدم).Add structured error responses: errorCategory (transient/validation/permission), an isRetryable boolean, and human-readable descriptions. Test that the agent handles each type appropriately (retry transient, explain business errors to the user).
  4. 4.نفّذ hook برمجياً يعترض استدعاءات الأدوات لفرض قاعدة عمل (مثل حجب عمليات فوق مبلغ معيّن)، ويحوّل لسير عمل تصعيد عند التفعيل.Implement a programmatic hook that intercepts tool calls to enforce a business rule (e.g., blocking operations above a threshold amount), redirecting to an escalation workflow when triggered.
  5. 5.اختبر برسائل متعددة الاهتمامات وتحقق أن الوكيل يفكك الطلب، يعالج كل اهتمام، ويوّلف رداً موحّداً.Test with multi-concern messages and verify the agent decomposes the request, handles each concern, and synthesizes a unified response.

إعداد Claude Code لسير عمل فريقConfigure Claude Code for a Team Development Workflow

الهدف: إعداد تسلسلات CLAUDE.md، أوامر مخصصة، قواعد حسب المسار، وتكامل خادم MCP لمشروع متعدد المطورين.Objective: practice configuring CLAUDE.md hierarchies, custom slash commands, path-specific rules, and MCP server integration for a multi-developer project.

  1. 1.أنشئ CLAUDE.md على مستوى المشروع بمعايير كود واختبار عامة. تحقق أن التعليمات على مستوى المشروع تُطبَّق باتساق عبر كل أعضاء الفريق.Create a project-level CLAUDE.md with universal coding and testing standards. Verify project-level instructions apply consistently across all team members.
  2. 2.أنشئ ملفات .claude/rules/ بـ YAML frontmatter وأنماط glob لمناطق كود مختلفة (مثل paths: ["src/api/**/*"] و["**/*.test.*"]). اختبر أن القواعد تُحمَّل فقط عند تعديل الملفات المطابقة.Create .claude/rules/ files with YAML frontmatter glob patterns for different areas (e.g. paths: ["src/api/**/*"] and ["**/*.test.*"]). Test that rules load only when editing matching files.
  3. 3.أنشئ skill على مستوى المشروع في .claude/skills/ بـ context: fork وقيود allowed-tools. تحقق أنه يشتغل في عزل بدون تلويث سياق المحادثة الرئيسي.Create a project-scoped skill in .claude/skills/ with context: fork and allowed-tools restrictions. Verify it runs in isolation without polluting the main conversation context.
  4. 4.اضبط خادم MCP في .mcp.json بتوسيع متغيرات البيئة للاعتمادات. أضف خادماً شخصياً تجريبياً في ~/.claude.json وتحقق من توفّر الاثنين معاً.Configure an MCP server in .mcp.json with environment-variable expansion for credentials. Add a personal experimental server in ~/.claude.json and verify both are available simultaneously.
  5. 5.اختبر plan mode مقابل التنفيذ المباشر على مهام بتعقيدات متفاوتة: إصلاح ملف واحد، هجرة مكتبة متعددة الملفات، وميزة جديدة بعدة نُهُج صالحة. لاحظ متى plan mode يعطي قيمة.Test plan mode vs direct execution on tasks of varying complexity: a single-file bug fix, a multi-file library migration, and a new feature with multiple valid approaches. Observe when plan mode adds value.

بناء خط استخراج بيانات مهيكلةBuild a Structured Data Extraction Pipeline

D4 D5

الهدف: تصميم مخططات JSON، واستخدام tool_use للمخرجات المهيكلة، وحلقات تحقّق-إعادة، واستراتيجيات معالجة دفعية.Objective: practice designing JSON schemas, using tool_use for structured output, implementing validation-retry loops, and designing batch processing strategies.

  1. 1.عرّف أداة استخراج بمخطط JSON فيه حقول إلزامية واختيارية، وenum بنمط "other" + سلسلة تفصيل، وحقول nullable لمعلومات قد لا توجد. عالج مستندات بعض حقولها غائبة وتحقق أن النموذج يرجع null بدل تلفيق قيم.Define an extraction tool with a JSON schema containing required and optional fields, an enum with an "other" + detail-string pattern, and nullable fields for information that may not exist. Process documents with absent fields and verify the model returns null rather than fabricating values.
  2. 2.نفّذ حلقة تحقّق-إعادة: عند فشل تحقق Pydantic أو JSON schema، أرسل طلباً لاحقاً يتضمن المستند والاستخراج الفاشل وخطأ التحقق المحدد. تتبّع أي الأخطاء يُحل بالإعادة (عدم تطابق الصيغة) وأيها لا (معلومة غائبة من المصدر).Implement a validation-retry loop: when Pydantic or JSON-schema validation fails, send a follow-up including the document, the failed extraction, and the specific validation error. Track which errors are resolvable via retry (format mismatches) vs not (information absent from source).
  3. 3.أضف أمثلة few-shot توضّح الاستخراج من مستندات بصيغ متنوعة (استشهادات مضمّنة مقابل قوائم مراجع، وصف سردي مقابل جداول) وتحقق من تحسّن معالجة التنوع البنيوي.Add few-shot examples demonstrating extraction from documents with varied formats (inline citations vs bibliographies, narrative vs structured tables) and verify improved handling of structural variety.
  4. 4.صمّم استراتيجية معالجة دفعية: أرسل دفعة 100 مستند عبر Message Batches API، عالج الإخفاقات بالـ custom_id، أعد إرسال الفاشلة بتعديلات (تقطيع المستندات الكبيرة)، واحسب زمن المعالجة الكلي مقابل قيود الـ SLA.Design a batch strategy: submit a batch of 100 documents via the Message Batches API, handle failures by custom_id, resubmit failed ones with modifications (chunking oversized documents), and compute total processing time against SLA constraints.
  5. 5.نفّذ استراتيجية توجيه مراجعة بشرية: خلّ النموذج يخرج درجات ثقة على مستوى الحقل، وجّه الاستخراجات منخفضة الثقة للمراجعة البشرية، وحلّل الدقة حسب نوع المستند والحقل للتأكد من أداء متسق.Implement a human-review routing strategy: have the model output field-level confidence scores, route low-confidence extractions to human review, and analyze accuracy by document type and field to verify consistent performance.

تصميم وتصحيح خط بحث متعدد الوكلاءDesign and Debug a Multi-Agent Research Pipeline

D1 D2 D5

الهدف: تنسيق وكلاء فرعيين، إدارة تمرير السياق، تنفيذ نشر الأخطاء، ومعالجة التوليف مع تتبّع المصدر.Objective: practice orchestrating subagents, managing context passing, implementing error propagation, and handling synthesis with provenance tracking.

  1. 1.ابنِ منسّقاً يفوّض لوكيلين فرعيين على الأقل (بحث ويب وتحليل مستندات). تأكد أن allowedTools للمنسّق يتضمن "Task"، وأن كل وكيل يستقبل نتائجه مباشرة في برومبته بدل الاعتماد على وراثة السياق تلقائياً.Build a coordinator that delegates to at least two subagents (web search and document analysis). Ensure the coordinator's allowedTools includes "Task", and each subagent receives its findings directly in its prompt rather than relying on automatic context inheritance.
  2. 2.نفّذ تنفيذاً متوازياً للوكلاء بأن يُصدر المنسّق عدة استدعاءات Task في رد واحد. قِس تحسّن زمن الاستجابة مقابل التنفيذ التسلسلي.Implement parallel subagent execution by having the coordinator emit multiple Task calls in a single response. Measure the latency improvement vs sequential execution.
  3. 3.صمّم مخرجات مهيكلة للوكلاء تفصل المحتوى عن الميتاداتا: كل نتيجة فيها ادعاء، مقتطف دليل، اسم/رابط المصدر، وتاريخ النشر. تحقق أن وكيل التوليف يحفظ إسناد المصدر عند الدمج.Design structured subagent output that separates content from metadata: each finding includes a claim, evidence excerpt, source URL/name, and publication date. Verify the synthesis subagent preserves source attribution when combining findings.
  4. 4.نفّذ نشر الأخطاء: حاكِ timeout لوكيل فرعي وتحقق أن المنسّق يستقبل سياق خطأ مهيكلاً (نوع الفشل، الاستعلام المحاول، نتائج جزئية). اختبر أنه يقدر يواصل بالنتائج الجزئية ويعلّم المخرَج بفجوات التغطية.Implement error propagation: simulate a subagent timeout and verify the coordinator receives structured error context (failure type, attempted query, partial results). Test that it can proceed with partial results and annotate the output with coverage gaps.
  5. 5.اختبر ببيانات مصدر متعارضة (مصدران موثوقان بإحصائيات مختلفة) وتحقق أن مخرَج التوليف يحفظ القيمتين مع إسناد المصدر بدل اختيار واحدة اعتباطاً، ويهيكل التقرير للتمييز بين النتائج الراسخة والمتنازع عليها.Test with conflicting source data (two credible sources with different statistics) and verify the synthesis output preserves both values with source attribution rather than arbitrarily picking one, structuring the report to distinguish well-established from contested findings.
