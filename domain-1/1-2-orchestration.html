تنسيق الأنظمة متعددة الوكلاء Orchestrating multi-agent systems

منسّق واحد يدير متخصصين — البنية اللي يقوم عليها سيناريو البحث كامل. جودة التقرير النهائي تتحدّد هنا: عند قرار التفكيك، قبل ما يشتغل أي وكيل فرعي. One coordinator managing specialists — the architecture the entire research scenario stands on. The final report's quality is decided here, at decomposition time, before any subagent even runs.

وش بتتعلم What you'll learn

  • ترسم بنية hub-and-spoke وتعلّل لماذا يمرّ كل اتصال بين الوكلاء عبر المنسّق.
  • تعرف أن الوكيل الفرعي يعمل بسياق معزول — لا يرث تاريخ محادثة المنسّق تلقائيًا.
  • تعدّد أدوار المنسّق: تفكيك المهمة، التفويض، تجميع النتائج، واختيار الوكلاء ديناميكيًا حسب تعقيد الطلب.
  • تشخّص خطر التفكيك الضيّق الذي يترك جوانب من الموضوع بلا تغطية.
  • تقسّم نطاق البحث بين الوكلاء (مواضيع فرعية أو أنواع مصادر مميّزة) لتقليل الازدواجية.
  • تبني حلقة تنقيح تكرارية: تقييم مخرجات التوليف، إعادة تفويض موجّهة، وإعادة توليف حتى تكفي التغطية.
  • Draw the hub-and-spoke architecture and justify why all inter-subagent communication routes through the coordinator.
  • Know that subagents run with isolated context — they don't automatically inherit the coordinator's conversation history.
  • Enumerate the coordinator's roles: task decomposition, delegation, result aggregation, and dynamically selecting subagents by query complexity.
  • Diagnose the overly-narrow decomposition risk that leaves parts of a broad topic uncovered.
  • Partition research scope across agents (distinct subtopics or source types) to minimize duplication.
  • Build an iterative refinement loop: evaluate synthesis output, re-delegate with targeted queries, and re-synthesize until coverage is sufficient.

01 بنية Hub-and-Spoke: كل الطرق تمرّ بالمنسّق Hub-and-spoke: every road runs through the coordinator

في نظام بحث متعدد الوكلاء (سيناريو 3)، البنية المعتمدة هي hub-and-spoke: وكيل منسّق في المركز يدير كل الاتصال بين الوكلاء الفرعيين، ومعالجة الأخطاء، وتوجيه المعلومات. الوكلاء الفرعيون لا يتكلمون مع بعض مباشرة أبدًا — وكيل البحث ما يسلّم نتائجه لوكيل التوليف؛ يسلّمها للمنسّق، والمنسّق يقرّر وش يوصل لمن.

ليش هالمركزية؟ ثلاثة مكاسب يذكرها الدليل نصًا: الرصد (observability) — نقطة واحدة تشوف منها كل تدفّق النظام وتصيد منها الأعطال؛ معالجة أخطاء متّسقة — فشل أي وكيل يصل للمنسّق فيقرّر: إعادة محاولة، بديل، أو المواصلة بنتائج جزئية؛ وتدفّق معلومات مضبوط — تتحكم بما يراه كل وكيل بدل فوضى نقل غير مراقب بين الأطراف.

ونقطة تُبنى عليها الصفحة القادمة كلها: الوكيل الفرعي يعمل بسياق معزول — ما يرث تاريخ محادثة المنسّق تلقائيًا. فكل معلومة يحتاجها لازم توصله صراحةً في برومبته.

In a multi-agent research system (Scenario 3), the established architecture is hub-and-spoke: a central coordinator agent manages all inter-subagent communication, error handling, and information routing. Subagents never talk to each other directly — the search agent doesn't hand its findings to the synthesis agent; it hands them to the coordinator, which decides what reaches whom.

Why centralize? Three gains the guide names explicitly: observability — one point from which you can watch the whole system's flow and catch failures; consistent error handling — any agent's failure reaches the coordinator, which decides: retry, alternative, or proceed with partial results; and controlled information flow — you govern what each agent sees instead of unmonitored peer-to-peer chatter.

And one point the next page is built on entirely: a subagent runs with isolated context — it does not automatically inherit the coordinator's conversation history. Everything it needs must reach it explicitly in its prompt.

spoke-to-spoke direct communication: NOT allowed

المنسّق في المركز، وكل سهم يمرّ به — الوكلاء الفرعيون لا يتواصلون مباشرة إطلاقًا. The coordinator sits at the hub and every arrow passes through it — spokes never communicate directly.

لمحة سريعة: لو سمحت للوكلاء بالتواصل المباشر «توفيرًا للوقت»، خسرت الثلاثة دفعة وحدة: الرصد، ومعالجة الأخطاء الموحّدة، والتحكم بتدفّق المعلومة. السرعة لها طريقها الصحيح: التوازي (صفحة 1.3) والأدوات المحدودة النطاق (الدومين 2).
Quick insight: allow direct spoke-to-spoke chatter "to save time" and you lose all three at once: observability, unified error handling, and controlled information flow. Speed has its proper channels: parallelism (page 1.3) and scoped tools (Domain 2).

02 وظيفة المنسّق: يفكّك، يفوّض، يجمّع — ويختار The coordinator's job: decompose, delegate, aggregate — and select

المنسّق مو مجرد «موزّع بريد». أدواره الأربعة: (1) تفكيك المهمة إلى مهام فرعية تغطّي الموضوع كاملًا؛ (2) التفويض لكل وكيل بنطاقه وسياقه؛ (3) تجميع النتائج ودمجها؛ و(4) — وهذا اللي يفرّق المعماري الشاطر — اختيار الوكلاء ديناميكيًا حسب تعقيد الطلب. سؤال بسيط مثل «متى تأسست شركة معيّنة؟» ما يحتاج أنبوب بحث + تحليل مستندات + توليف + تقرير كامل؛ يكفيه وكيل البحث وحده. تمرير كل طلب عبر الأنبوب الكامل يحرق وقتًا وتوكنز بلا فائدة.

وعند التفويض لعدة وكلاء: قسّم النطاق بحيث يقلّ التكرار — أعطِ كل وكيل موضوعًا فرعيًا مميّزًا (الاقتصاد لواحد، التقنية لثاني) أو نوع مصادر مميّزًا (أوراق أكاديمية لواحد، أخبار الصناعة لثاني). بدون تقسيم صريح بيرجعون لك بنفس المقالات الخمس المشهورة.

The coordinator is not a mail sorter. Its four roles: (1) decompose the task into subtasks that cover the whole topic; (2) delegate each agent its scope and context; (3) aggregate results and merge them; and (4) — the one that separates good architects — dynamically select which subagents to invoke based on query complexity. A simple question like "when was some company founded?" doesn't need the full search + document analysis + synthesis + report pipeline; the search agent alone suffices. Routing everything through the full pipeline burns time and tokens for nothing.

And when delegating to several agents: partition the scope to minimize duplication — give each agent a distinct subtopic (economics to one, technology to another) or a distinct source type (academic papers vs industry news). Without explicit partitioning, they all come back with the same five famous articles.

مفهوم أساسي: جودة النظام متعدد الوكلاء تتحدّد عند قرار التفكيك. الوكلاء الفرعيون ينفّذون النطاق المُسنَد بأمانة — فإذا كان النطاق ناقصًا، سينفّذون النقص بأمانة أيضًا.
Key concept: a multi-agent system's quality is decided at decomposition time. Subagents execute their assigned scope faithfully — so if the scope is incomplete, they will faithfully execute the incompleteness too.

03 الفخ الأكبر: التفكيك الضيّق The biggest trap: narrow decomposition

السيناريو الكلاسيكي في الاختبار: نظام بحث كل وكلائه «نجحوا» — البحث لقى مقالات ممتازة، التحليل لخّص بدقة، التوليف كتب تقريرًا متماسكًا — ومع ذلك التقرير النهائي يغطّي زاوية وحدة من موضوع عريض. تفتح سجلات المنسّق فتلقى التفكيك نفسه ضيّقًا: موضوع «أثر الذكاء الاصطناعي على الصناعات الإبداعية» انقسم إلى ثلاث مهام كلها فنون بصرية، وما ذُكرت الموسيقى ولا الكتابة ولا الأفلام أصلًا.

الدرس المزدوج: تشخيصيًا — لما يكون الناتج ناقصًا وكل وكيل «ناجح»، وجّه الشك أولًا لقرار التفكيك، مو للوكلاء. وقائيًا — اكتب برومبت المنسّق بحيث يُلزمه بتغطية كل مجالات الموضوع قبل التوزيع، وفعّل حلقة تنقيح (القسم التالي) تكتشف الفجوات وتسدّها.

The classic exam scenario: a research system where every agent "succeeded" — search found excellent articles, analysis summarized accurately, synthesis wrote a coherent report — yet the final report covers a single angle of a broad topic. Open the coordinator's logs and the decomposition itself is narrow: "the impact of AI on creative industries" was split into three tasks that are all visual arts, with music, writing, and film never mentioned at all.

The double lesson: diagnostically — when output is incomplete and every agent "succeeded," point suspicion first at the decomposition decision, not the agents. Preventively — write the coordinator prompt to require covering all domains of the topic before distributing, and run a refinement loop (next section) that detects and closes gaps.

نفس الموضوع، تفكيكان: الأيسر ينتج تقريرًا «ناجح الوكلاء، فاشل التغطية»؛ الأيمن يغطّي المجال كاملًا. Same topic, two decompositions: one yields a report where agents succeed but coverage fails; the other spans the whole field.

تنبيه: لو التقرير النهائي ناقص، أول شك يروح على قرار التفكيك عند المنسّق، مو على الوكلاء الفرعيين. الوكلاء غالبًا نفّذوا نطاقهم المُسنَد بإتقان — المشكلة في ما الذي أُسند إليهم.
Warning: when the final report is incomplete, suspect the coordinator's decomposition first, not the subagents. They almost certainly executed their assigned scope faithfully — the problem is what they were assigned.

04 حلقة التنقيح التكرارية: سدّ الفجوات قبل التسليم The iterative refinement loop: close gaps before delivering

حتى مع تفكيك جيد، الجولة الأولى نادرًا ما تكفي لموضوع عريض. النمط الذي يطلبه الدليل: المنسّق يقيّم مخرجات التوليف بحثًا عن فجوات، وإذا وجدها يعيد التفويض لوكلاء البحث والتحليل بأسئلة موجّهة نحو الفجوة تحديدًا (مو بإعادة البحث من الصفر)، ثم يعيد استدعاء التوليف بالأدلة الجديدة — ويكرّر حتى تكفي التغطية. هذي الحلقة هي العلاج المعماري الدائم للتفكيك الناقص: حتى لو فاتت المنسّقَ زاويةٌ في الجولة الأولى، التقييم يلتقطها.

Even with good decomposition, one round is rarely enough for a broad topic. The pattern the guide requires: the coordinator evaluates the synthesis output for gaps, and when it finds them it re-delegates to the search and analysis subagents with targeted queries aimed at the specific gap (not re-searching from scratch), then re-invokes synthesis with the new evidence — repeating until coverage is sufficient. This loop is the durable architectural cure for incomplete decomposition: even if the coordinator missed an angle in round one, evaluation catches it.

منسّق: اختيار ديناميكي + حلقة تنقيح لسدّ الفجوات Coordinator: dynamic selection + a refinement loop that closes gaps 
def coordinate(query):
    # 1) Analyze the query and pick ONLY the subagents it needs
    plan   = analyze(query)
    agents = select_subagents(plan)          # dynamic selection by complexity
    if plan.is_simple_lookup:
        return run_subagents(["web_search"], plan.direct_query)

    # 2) Partition scope so agents don't duplicate each other's work
    #    (distinct subtopics or distinct source types per agent)
    findings = run_subagents(agents, partition_scope(plan))
    report   = synthesize(findings)

    # 3) Iterative refinement: evaluate -> re-delegate -> re-synthesize
    while has_coverage_gaps(report):
        gaps  = identify_gaps(report)        # e.g. "no findings on music/film"
        more  = run_subagents(["web_search", "doc_analysis"],
                              targeted_queries(gaps))
        findings += more
        report   = synthesize(findings)      # re-run synthesis with new evidence

    return report                            # everything flowed through the hub

فخ الاختبارExam trap

  • تقرير ناقص مع نجاح كل الوكلاء ← الخيارات اللي تلوم البحث أو التحليل أو التوليف كلها مشتّتات؛ الجواب: تفكيك المنسّق ضيّق.Incomplete report while every agent succeeded — options blaming search, analysis, or synthesis are all distractors; the answer: the coordinator's decomposition is too narrow.
  • «شغّل الأنبوب الكامل على كل طلب لضمان الجودة» — عكس الاختيار الديناميكي الذي يطلبه الدليل."Run the full pipeline on every query to guarantee quality" — the opposite of the dynamic selection the guide requires.
  • «خلّ وكيل البحث يرسل نتائجه لوكيل التوليف مباشرة لتقليل الخطوات» — يكسر الرصد ومعالجة الأخطاء الموحّدة."Let the search agent send findings straight to synthesis to cut steps" — breaks observability and unified error handling.
  • فجوات تغطية بعد التوليف ← الجواب حلقة تنقيح بإعادة تفويض موجّهة، مو «أعد البحث كله من الصفر».Coverage gaps after synthesis — the answer is a refinement loop with targeted re-delegation, not "redo all the research from scratch."

مثال من الحياة: رئيس تحرير المجلة Real-life example: the magazine editor-in-chief

مجلة تجهّز ملفًا خاصًا عن «الحياة في المدن الذكية». رئيس التحرير هو المنسّق: يفكّك الملف إلى زوايا (النقل، الطاقة، الخصوصية، الاقتصاد) ويوزّعها على محررين متخصصين (الوكلاء الفرعيين)، لكل واحد زاوية مختلفة عشان ما يتكرر الشغل. المحررون ما ينسّقون مع بعض مباشرة — كل مسودة تمرّ على مكتب رئيس التحرير: هو اللي يشوف الصورة كاملة، يعالج تعارض المعلومات، ويقرّر وش ينشر.

لو طلع العدد كله عن النقل فقط، مين الملوم؟ مو المحررين — كل واحد غطّى زاويته المكلّف بها باحتراف. الملوم ورقة التوزيع الضيّقة اللي كتبها رئيس التحرير. ورئيس التحرير الشاطر يسوي «حلقة تنقيح»: يقرأ المسودة المجمّعة، يكتشف أن زاوية الخصوصية ضعيفة، فيرجّع محررها بأسئلة محددة — مو بإعادة كتابة الملف كله. وإذا كان الموضوع خبرًا عاجلًا بسيطًا؟ يرسله لمحرر واحد بدل تجنيد الفريق كامل — هذا هو الاختيار الديناميكي.

A magazine is preparing a special issue on "life in smart cities." The editor-in-chief is the coordinator: he decomposes the issue into angles (transport, energy, privacy, economy) and assigns them to specialist editors (the subagents), each with a distinct angle so no work is duplicated. The editors don't coordinate with each other directly — every draft crosses the editor-in-chief's desk: he sees the full picture, resolves conflicting facts, and decides what gets published.

If the issue comes out covering only transport, who's at fault? Not the editors — each covered their assigned angle professionally. The fault lies in the narrow assignment sheet the chief wrote. And a good chief runs a "refinement loop": reading the assembled draft, noticing the privacy angle is thin, and sending its editor back with specific follow-up questions — not rewriting the entire issue. A simple breaking-news item? He sends one editor instead of mobilizing the whole team — that's dynamic selection.

في الاختبارOn the exam

أسئلة 1.2 تدور حول «مين المسؤول؟»: يعطونك أعراضًا (تقرير ناقص، ازدواجية نتائج، بطء) وسجلات المنسّق، ويطلبون السبب الجذري أو الإصلاح المعماري.

  • اقرأ سجلات المنسّق في السؤال أولًا: لو المهام المسندة نفسها ضيّقة، فالجواب جاهز مهما حاولت المشتّتات لوم وكلاء المصبّ.
  • الحلول الصحيحة تتكلم بلغة: اختيار ديناميكي، تقسيم نطاق، حلقة تنقيح موجّهة، توجيه كل الاتصال عبر المنسّق.
  • استبعد: أي خيار يجعل الوكلاء يتواصلون مباشرة، وأي خيار يعالج فجوات التغطية بإعادة كل البحث بدل استعلامات موجّهة.

Task 1.2 questions revolve around "who is responsible?": you get symptoms (incomplete report, duplicated findings, slowness) plus coordinator logs, and must name the root cause or the architectural fix.

  • Read the coordinator's logs in the stem first: if the assigned subtasks are themselves narrow, the answer is settled no matter how hard the distractors blame downstream agents.
  • Correct options speak the language of: dynamic selection, scope partitioning, targeted refinement loops, all communication through the coordinator.
  • Eliminate: any option letting subagents talk directly, and any option fixing coverage gaps by redoing all research instead of targeted queries.

خلاصةTakeaway

  • Hub-and-spoke: كل الاتصال عبر المنسّق — رصد، أخطاء موحّدة، تدفّق مضبوط.
  • سياق الوكيل الفرعي معزول — لا وراثة تلقائية لتاريخ المنسّق.
  • المنسّق يختار الوكلاء ديناميكيًا حسب التعقيد ويقسّم النطاق لتقليل الازدواجية.
  • ناتج ناقص + وكلاء «ناجحون» = تفكيك ضيّق عند المنسّق.
  • العلاج الدائم: حلقة تنقيح — تقييم، إعادة تفويض موجّهة، إعادة توليف.
  • Hub-and-spoke: all communication through the coordinator — observability, unified errors, controlled flow.
  • Subagent context is isolated — no automatic inheritance of the coordinator's history.
  • The coordinator selects subagents dynamically by complexity and partitions scope to minimize duplication.
  • Incomplete output + "successful" agents = narrow decomposition at the coordinator.
  • The durable cure: a refinement loop — evaluate, re-delegate targeted, re-synthesize.
