1.3

استدعاء الوكلاء الفرعيين وتمرير السياق والإطلاق Subagent invocation, context passing & spawning

أقوى منسّق في الدنيا بلا تمرير سياق صحيح = وكلاء يشتغلون في الظلام. هنا التفاصيل التقنية: أداة Task، وقاعدة «لا وراثة تلقائية»، والتوازي الصحيح. The mightiest coordinator with broken context passing = agents working in the dark. Here are the mechanics: the Task tool, the "no automatic inheritance" rule, and doing parallelism right.

وش بتتعلم What you'll learn

  • تطلق الوكلاء الفرعيين بأداة Task، وتعرف أن allowedTools عند المنسّق لازم تتضمّن "Task".
  • تعرّف كل نوع وكيل بـ AgentDefinition: وصف، برومبت نظام، وقيود أدوات.
  • تمرّر السياق صراحةً: نتائج الوكلاء السابقين كاملة داخل برومبت الوكيل الفرعي — لا وراثة ولا ذاكرة مشتركة.
  • تفصل المحتوى عن الميتاداتا (روابط المصادر، أسماء المستندات، أرقام الصفحات) بصيغ منظّمة تحفظ الإسناد.
  • تشغّل وكلاء بالتوازي بإصدار عدة نداءات Task في رد واحد — لا عبر أدوار متتابعة.
  • تكتب برومبتات منسّق تحدّد الأهداف ومعايير الجودة بدل الإجراءات خطوة-بخطوة، وتعرف دور fork للجلسات (تفصيلها في 1.7).
  • Spawn subagents with the Task tool, and know the coordinator's allowedTools must include "Task".
  • Define each agent type with an AgentDefinition: description, system prompt, and tool restrictions.
  • Pass context explicitly: complete findings from prior agents go inside the subagent's prompt — no inheritance, no shared memory.
  • Separate content from metadata (source URLs, document names, page numbers) with structured formats that preserve attribution.
  • Run agents in parallel by emitting multiple Task calls in a single response — not across sequential turns.
  • Write coordinator prompts that state goals and quality criteria instead of step-by-step procedures, and know fork-based sessions (detailed in 1.7).

01 أداة Task و AgentDefinition: عدّة الإطلاق The Task tool & AgentDefinition: the spawning kit

آلية إطلاق الوكلاء الفرعيين هي أداة Task المدمجة: المنسّق «يستدعي أداة» اسمها Task، ومدخلاتها تحدّد نوع الوكيل الفرعي والبرومبت الذي سيستلمه. وهنا شرط صلب ينساه كثيرون: لازم قائمة allowedTools عند المنسّق تتضمّن "Task" — بدونها المنسّق ببساطة لا يستطيع التفويض إطلاقًا، مهما كان برومبته بليغًا.

كل نوع وكيل فرعي تعرّفه بـ AgentDefinition من ثلاثة أجزاء: الوصف (متى يُستدعى هذا الوكيل — يقرؤه المنسّق)، برومبت النظام (شخصية الوكيل وأسلوب مخرجاته)، وقيود الأدوات (وكيل البحث ياخذ أدوات البحث فقط؛ وكيل التوليف بلا أدوات بحث أصلًا — فصل الاختصاصات هذا يتوسّع فيه الدومين 2).

The mechanism for spawning subagents is the built-in Task tool: the coordinator "calls a tool" named Task whose input specifies the subagent type and the prompt it will receive. And here is a hard requirement people forget: the coordinator's allowedTools must include "Task" — without it, the coordinator simply cannot delegate at all, however eloquent its prompt.

Each subagent type is declared with an AgentDefinition in three parts: the description (when to invoke this agent — read by the coordinator), the system prompt (the agent's persona and output style), and tool restrictions (the search agent gets search tools only; the synthesis agent gets no search tools at all — a separation of concerns Domain 2 expands on).

تعريف الوكلاء وإطلاقهم بالتوازي (Agent SDK) Defining agents and spawning them in parallel (Agent SDK) 
from claude_agent_sdk import query, ClaudeAgentOptions, AgentDefinition

# Each subagent runs in ISOLATED context: it only sees what you put in its prompt.
research_agents = {
    "web_search": AgentDefinition(
        description="Searches the web for sources on an ASSIGNED subtopic.",
        prompt=("You are a web research specialist. Return findings as structured "
                "items: {claim, evidence, source_url, published_date}."),
        tools=["WebSearch", "WebFetch"],       # scoped tools only
    ),
    "doc_analysis": AgentDefinition(
        description="Analyzes documents and extracts cited claims.",
        prompt="Extract claims with source name, page number, and a short excerpt.",
        tools=["Read", "Grep"],
    ),
    "synthesis": AgentDefinition(
        description="Merges findings into a single cited report.",
        prompt=("Combine ONLY the findings provided in your prompt. "
                "Preserve every claim-to-source mapping."),
        tools=[],                              # no search tools: separation of concerns
    ),
}

options = ClaudeAgentOptions(
    agents=research_agents,
    allowed_tools=["Task"],                    # REQUIRED to spawn subagents
    system_prompt=(
        "You are a research coordinator. Decompose the topic to cover ALL of its "
        "domains. Spawn independent subagents IN PARALLEL by emitting multiple Task "
        "calls in a SINGLE response. Pass each subagent the exact findings it needs "
        "-- subagents do NOT inherit your context. Specify goals and quality "
        "criteria, not step-by-step procedures."
    ),
)

async for message in query(
    prompt="Research the impact of AI on creative industries",
    options=options,
):
    print(message)
لمحة سريعة: أعراض «المنسّق يوصف الخطة لكن ما يفوّض أحدًا أبدًا» لها تشخيص واحد شائع: "Task" ناقصة من allowedTools. افحص الإعدادات قبل ما تلوم البرومبت.
Quick insight: the symptom "the coordinator describes the plan but never actually delegates" has one common diagnosis: "Task" is missing from allowedTools. Check the config before blaming the prompt.

02 تمرير السياق صراحةً: لا وراثة، لا ذاكرة مشتركة Explicit context passing: no inheritance, no shared memory

القاعدة اللي ينكسر عليها أكثر المهندسين: الوكيل الفرعي لا يرث سياق الأب ولا يشارك ذاكرة بين الاستدعاءات. كل استدعاء Task يفتح عالمًا نظيفًا معزولًا: ما فيه تاريخ المنسّق، ولا نتائج الوكلاء الآخرين، ولا حتى نتائج استدعاء سابق لنفس الوكيل. عبارة «بناءً على النتائج السابقة» في برومبت وكيل فرعي = جملة بلا معنى في عالمه.

الحل من شقّين. الأول: التضمين الكامل — إذا احتاج وكيل التوليف نتائج البحث وتحليل المستندات، تحطّها حرفيًا داخل برومبته. الثاني: صيغة منظّمة تفصل المحتوى عن الميتاداتا — كل نتيجة تُمرَّر كعنصر فيه الادّعاء (claim) والدليل (evidence) منفصلين عن بيانات المصدر (رابط، اسم مستند، رقم صفحة، تاريخ نشر). ليش؟ لأن حشر كل شيء في نص حر يذوّب الإسناد: بعد تلخيصين ما عاد أحد يعرف أي ادّعاء جاء من أي مصدر — والحفاظ على الإسناد مطلب مركزي في سيناريو البحث (ويرجع بقوة في الدومين 5).

The rule most engineers break first: a subagent does not inherit its parent's context and shares no memory between invocations. Every Task call opens a clean, isolated world: no coordinator history, no other agents' findings, not even the output of a previous invocation of the same agent. The phrase "based on the earlier findings" in a subagent prompt is a meaningless sentence in its world.

The fix has two parts. First: full inclusion — if the synthesis agent needs the web search and document analysis outputs, you place them verbatim inside its prompt. Second: a structured format separating content from metadata — each finding is passed as an item with the claim and evidence kept apart from source data (URL, document name, page number, publication date). Why? Because dumping everything into free text dissolves attribution: two summaries later, nobody knows which claim came from which source — and preserving attribution is central to the research scenario (and returns hard in Domain 5).

coordinator
prompt = task + ALL findings + metadata
synthesis subagent
"automatic context inheritance" -- does not exist. Anything not in the prompt is invisible.
structured finding (content vs metadata):
content
claim: "AI tools cut design time 40%"
evidence: "...survey of 1,200 studios..."
metadata
source_url, document, page: 14
published_date: 2025-11-02

السياق يوصل بطريق واحد فقط: حقنه صراحةً في البرومبت — بصيغة تفصل الادّعاء عن بيانات مصدره. Context travels one way only: injected explicitly into the prompt — in a format separating each claim from its source data.

مفهوم أساسي: برومبت الوكيل الفرعي هو كامل عالمه. صمّمه كأنك ترسل ملف عمل لمستشار خارجي ما حضر أي اجتماع: المهمة، وكل المعطيات، ومعايير القبول — كلها داخل الملف.
Key concept: a subagent's prompt is its entire universe. Design it like a work file sent to an external consultant who attended no meetings: the task, every input, and the acceptance criteria — all inside the file.

03 التوازي الصحيح: عدة نداءات Task في رد واحد Parallelism done right: multiple Task calls in one response

للمهام المستقلة (البحث في محور الاقتصاد + البحث في محور التقنية)، الفرق بين التوازي والتتابع هو الفرق بين انتظار أبطأ وكيل وانتظار مجموعهم. الطريقة الصحيحة للتوازي: المنسّق يُصدر عدة نداءات Task في رد واحد — كتل tool_use متجاورة في نفس الرسالة — فتنطلق كلها معًا. الطريقة الخاطئة الشائعة: نداء Task واحد في كل دور، ينتظر نتيجته، ثم يطلق التالي — نفس الشغل بزمن تراكمي.

For independent tasks (researching the economics angle + the technology angle), parallel vs sequential is the difference between waiting for the slowest agent and waiting for the sum of all of them. The right way to parallelize: the coordinator emits multiple Task calls in a single response — adjacent tool_use blocks in the same message — so they all launch together. The common wrong way: one Task call per turn, wait for its result, then launch the next — the same work at cumulative latency.

GOOD — one response
coordinator response #1:
Task(web_search) Task(doc_analysis) Task(data_check)
all run concurrently -- wall time = slowest agent
BAD — sequential turns
turn 1: Task(web_search) ... wait
turn 2: Task(doc_analysis) ... wait
turn 3: Task(data_check) ... wait
wall time = sum of all three

وكلاء مستقلون؟ أطلقهم كلهم في رد واحد. التتابع للدورات المعتمدة على نتائج بعضها فقط. Independent agents? Launch them all in one response. Sequential turns are only for steps that depend on each other's results.

04 أهداف لا إجراءات Goals, not procedures

آخر مهارة في هذا الموضوع تخصّ صياغة برومبت المنسّق نفسه: حدّد أهداف البحث ومعايير الجودة («غطِّ كل مجالات الموضوع؛ كل ادّعاء له مصدر وتاريخ؛ فضّل مصادر أحدث من 2023») بدل تعليمات إجرائية خطوة-بخطوة («أولًا ابحث بكلمة كذا، ثم افتح أول ثلاث نتائج...»). الأهداف تترك للوكلاء الفرعيين حرية التكيّف مع ما يكتشفونه؛ الإجراءات المفصّلة تقتل هذي المرونة وتعيدك عمليًا لشجرة قرارات جامدة — نفس الفخ اللي حذّرنا منه في 1.1. وللاستكشاف المتوازي لنهجين مختلفين من أساس مشترك، الدليل يشير لإدارة الجلسات بالتفريع (fork) — تفاصيلها الكاملة في صفحة 1.7.

The last skill in this topic concerns the coordinator prompt itself: specify research goals and quality criteria ("cover all domains of the topic; every claim carries a source and date; prefer sources newer than 2023") instead of step-by-step procedural instructions ("first search for this keyword, then open the top three results..."). Goals leave subagents free to adapt to what they discover; detailed procedures kill that flexibility and effectively drag you back to a rigid decision tree — the same trap 1.1 warned about. And for exploring two divergent approaches from a shared baseline, the guide points to fork-based session management — fully detailed on page 1.7.

نصيحة: اختبر برومبت المنسّق بسؤال: «لو تغيّر الواقع في منتصف الشغل، هل تسمح الصياغة للوكيل بتعديل خطته؟» إذا كان الجواب لا، فأنت تكتب إجراءات مو أهدافًا.
Tip: test your coordinator prompt with one question: "if reality shifts mid-task, does the wording let the agent adjust its plan?" If the answer is no, you are writing procedures, not goals.

فخ الاختبارExam trap

  • افتراض أن وكيل التوليف «يشوف» نتائج البحث تلقائيًا — لا؛ السياق لازم يُحقن في برومبته صراحةً وكاملًا.Assuming the synthesis agent automatically "sees" the search findings — no; context must be injected into its prompt, explicitly and completely.
  • إطلاق وكلاء مستقلين عبر أدوار متتابعة (Task واحدة لكل دور) — التوازي الصحيح: عدة نداءات في رد واحد.Spawning independent agents across sequential turns (one Task per turn) — correct parallelism is multiple calls in one response.
  • نسيان "Task" من allowedTools ثم لوم البرومبت لما يعجز المنسّق عن التفويض.Omitting "Task" from allowedTools, then blaming the prompt when the coordinator can't delegate.
  • تمرير النتائج كنص حر مدموج بلا فصل محتوى/ميتاداتا — يضيّع الإسناد أثناء التوليف.Passing findings as merged free text with no content/metadata separation — attribution dissolves during synthesis.

مثال من الحياة: تذاكر المطبخ في مطعم مزدحم Real-life example: kitchen tickets in a busy restaurant

الشيف التنفيذي (المنسّق) يستلم طلب طاولة كاملة ويوزّعه على أقسام المطبخ: الشواية، السلطات، الحلويات (الوكلاء الفرعيون). قسم الحلويات ما سمع كلام الزبون أبدًا — كل اللي يعرفه مكتوب في التذكرة اللي وصلته: «تشيز كيك، بدون فراولة — حساسية». هذا هو تمرير السياق الصريح: لو ما كُتبت الحساسية في التذكرة، القسم ما يعرف عنها شيئًا، مهما تكلم الزبون مع الشيف قبل شوي. والتذكرة نفسها منظّمة: الصنف والتعديلات (المحتوى) في خانة، ورقم الطاولة والوقت (الميتاداتا) في خانة — عشان يعرف كل طبق يرجع لأي طاولة.

والتوازي؟ الشيف الشاطر يعلّق تذاكر الطاولة كلها دفعة وحدة فتشتغل الأقسام الثلاثة بنفس الوقت ويطلع العشاء كاملًا سوا — هذا «عدة نداءات Task في رد واحد». الشيف الضعيف يسلّم تذكرة، ينتظر الصحن، ثم يسلّم اللي بعدها: نفس الأصناف، لكن السلطة ذابلة والزبون طفش (أدوار متتابعة). ولاحظ صيغة التذاكر: الشيف يكتب «ستيك وسط مع صوص الفلفل» — الهدف ومعيار الجودة — وما يمسك يد الطبّاخ خطوة خطوة: القسم أعرف بشغله.

The executive chef (coordinator) takes a full table's order and distributes it across kitchen stations: grill, salads, desserts (the subagents). The dessert station never heard the customer speak — everything it knows is written on the ticket it received: "cheesecake, no strawberries — allergy." That is explicit context passing: if the allergy isn't written on the ticket, the station knows nothing about it, no matter how long the customer chatted with the chef. And the ticket itself is structured: item and modifications (content) in one field, table number and time (metadata) in another — so every dish finds its way back to the right table.

Parallelism? A good chef fires all the table's tickets at once so all three stations cook simultaneously and dinner arrives together — that is "multiple Task calls in one response." A weak chef hands over one ticket, waits for the plate, then hands over the next: same dishes, but the salad has wilted and the customer is fuming (sequential turns). Note the ticket's wording too: the chef writes "steak medium, pepper sauce" — the goal and quality bar — without hand-holding the cook step by step: the station knows its craft.

في الاختبارOn the exam

أسئلة 1.3 عملية جدًا: إعدادات SDK فيها خطأ واحد قاتل، أو وكيل توليف طلعت مخرجاته «فاضية» من النتائج، أو سؤال أداء عن تسريع وكلاء مستقلين.

  • ثبّت الثلاثية: Task في allowedTools + سياق كامل محقون في البرومبت + نداءات متعددة في رد واحد للتوازي.
  • لما يسأل عن حفظ الإسناد أثناء تمرير النتائج، الجواب: صيغة منظّمة تفصل المحتوى (claim/evidence) عن الميتاداتا (مصدر/صفحة/تاريخ).
  • استبعد أي خيار يذكر «وراثة تلقائية للسياق» أو «ذاكرة مشتركة بين الوكلاء» — هذي ميزات غير موجودة.
  • واستبعد برومبتات المنسّق المليئة بإجراءات خطوة-بخطوة — الدليل يطلب أهدافًا ومعايير جودة.

Task 1.3 questions are hands-on: an SDK config with one fatal mistake, a synthesis agent whose output came back "empty" of findings, or a performance question about speeding up independent agents.

  • Lock in the trio: Task inside allowedTools + full context injected in the prompt + multiple calls in one response for parallelism.
  • When asked how to preserve attribution while passing findings: a structured format separating content (claim/evidence) from metadata (source/page/date).
  • Eliminate any option mentioning "automatic context inheritance" or "shared agent memory" — those features do not exist.
  • Also eliminate coordinator prompts stuffed with step-by-step procedures — the guide demands goals and quality criteria.

صحيح. الصيغة المنظّمة التي تفصل المحتوى عن الميتاداتا هي ما ينصّ عليه الدليل لحفظ الإسناد — التوليف يدمج الادّعاءات ويبقي خريطة «ادّعاء ← مصدر» سليمة. Correct. A structured format separating content from metadata is exactly what the guide prescribes for preserving attribution — synthesis merges claims while the claim-to-source mapping stays intact.
خطأ. الصحيح: عناصر منظّمة تفصل المحتوى عن الميتاداتا. السرد الحر يذوّب الإسناد، وقائمة الروابط تعيد شغل البحث كاملًا (ووكيل التوليف أصلًا بلا أدوات بحث)، والملخّص المفرط يفقد التفاصيل والدلائل. Not quite. The correct format: structured items separating content from metadata. Free narrative dissolves attribution, a URL list redoes the search work (and the synthesis agent has no search tools anyway), and an over-compressed summary loses details and evidence.

خلاصةTakeaway

  • الإطلاق عبر أداة Task، وشرطه "Task" داخل allowedTools.
  • كل وكيل = AgentDefinition: وصف + برومبت + قيود أدوات.
  • لا وراثة ولا ذاكرة مشتركة: السياق كاملًا داخل برومبت الوكيل، بصيغة تفصل المحتوى عن الميتاداتا.
  • التوازي = عدة نداءات Task في رد واحد.
  • برومبت المنسّق: أهداف ومعايير جودة — مو إجراءات خطوة-بخطوة.
  • Spawning goes through the Task tool, gated on "Task" inside allowedTools.
  • Each agent = an AgentDefinition: description + prompt + tool restrictions.
  • No inheritance, no shared memory: full context goes inside the agent's prompt, content separated from metadata.
  • Parallelism = multiple Task calls in one response.
  • Coordinator prompts: goals and quality criteria — not step-by-step procedures.
