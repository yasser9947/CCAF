الأوامر المخصّصة والمهارات Custom slash commands & skills

سير عمل الفريق المتكرر يستحق أمراً يُكتب مرة ويُستدعى بضغطة — ومهارة تعرف حدود صلاحياتها وسياقها. Repeated team workflows deserve a command written once and invoked instantly — and a skill that knows its privilege and context boundaries.

وش بتتعلمWhat you'll learn

  • أوامر المشروع في .claude/commands/ (تُشارَك عبر Git) مقابل الأوامر الشخصية في ~/.claude/commands/Project commands in .claude/commands/ (shared via Git) vs personal commands in ~/.claude/commands/
  • بنية المهارة: مجلد في .claude/skills/ بملف SKILL.md له frontmatter يضبط سلوكهاSkill anatomy: a folder in .claude/skills/ with a SKILL.md whose frontmatter configures behavior
  • context: fork لعزل المخرجات الطويلة والاستكشافية، وallowed-tools لتقييد الأدوات، وargument-hint لطلب المعطى الناقصcontext: fork to isolate verbose or exploratory output, allowed-tools to restrict tools, argument-hint to prompt for missing parameters
  • التخصيص الشخصي: نسخة في ~/.claude/skills/ باسم مختلف حتى لا تؤثر على الزملاءPersonal customization: a variant in ~/.claude/skills/ with a different name so teammates are unaffected
  • قرار التصميم الجوهري: مهارة (تُستدعى عند الطلب لسير عمل محدد) أم CLAUDE.md (معايير عامة محمَّلة دائماً)؟The core design decision: a skill (on-demand, task-specific workflow) or CLAUDE.md (universal, always-loaded standards)?

أوامر slash: الموقع يحدد من يستفيد Slash commands: location decides who benefits

الأمر المخصّص ملف markdown بسيط: تكتب فيه البرومبت مرة واحدة، ويستدعيه أي مطوّر بكتابة /اسم-الملف. السطر الفاصل في كل أسئلة هذا الموضوع هو مكان الملف:

  • .claude/commands/ داخل المستودع — أوامر المشروع: تدخل التحكم بالإصدارات، فيستلمها تلقائياً كل من يستنسخ أو يسحب. هذا هو البيت الصحيح لأمر /review يشغّل قائمة مراجعة الفريق.
  • ~/.claude/commands/ في مجلد المنزل — أوامر شخصية: على جهازك فقط، لا يراها أحد غيرك.

ولاحظ ما ليس مكاناً للأوامر: CLAUDE.md (للتعليمات والسياق، لا لتعريف أوامر)، وملف .claude/config.json بمصفوفة commands (آلية غير موجودة يحبها كتّاب الأسئلة كخيار فخ).

A custom slash command is a simple markdown file: write the prompt once, and any developer invokes it by typing /file-name. The dividing line in every question on this topic is where the file lives:

  • .claude/commands/ inside the repository — project commands: version-controlled, automatically received by everyone who clones or pulls. This is the right home for a team /review command running the shared checklist.
  • ~/.claude/commands/ in your home directory — personal commands: on your machine only, invisible to everyone else.

Note what is not a command location: CLAUDE.md (instructions and context, not command definitions), and a .claude/config.json with a commands array (a mechanism that does not exist — a favorite trap option).

العمود الأيسر (بنفسجي) يعيش في المستودع ويصل للجميع؛ الأيمن (رمادي) شخصي على جهازك — والنسخة الشخصية من مهارة الفريق تأخذ اسماً مختلفاً. The violet column lives in the repo and reaches everyone; the gray column is personal on your machine — and a personal variant of a team skill takes a different name.

مثال: أمر مشروع .claude/commands/review.mdExample: project command .claude/commands/review.md
---
description: Run the team's standard code-review checklist
argument-hint: [pr-number]
---
Review the changes for PR #$ARGUMENTS against our checklist:

- Correctness and edge cases (null, empty, boundary values)
- Test coverage for every new branch
- No secrets, debug logging, or commented-out code left behind
- Naming and error handling match .claude/rules/api-conventions.md

Report findings grouped by severity: blocker / warning / nit.
لمحة سريعةQuick insight
عبارة «متاح لكل مطوّر عند الاستنساخ / available on clone» في السؤال = المكان داخل المستودع (.claude/…). عبارة «بدون التأثير على الزملاء / without affecting teammates» = المكان الشخصي (~/.claude/…) وباسم مختلف للمهارات.
"Available to every developer on clone" in a question = the in-repo location (.claude/…). "Without affecting teammates" = the personal location (~/.claude/…), with a different name for skills.

المهارات: تشريح SKILL.md وقوة الـ frontmatter Skills: SKILL.md anatomy & frontmatter powers

المهارة أقوى من الأمر: مجلد كامل في .claude/skills/ قلبه ملف SKILL.md، وترويسته (frontmatter) تمنحك ثلاث أدوات تحكم يسأل عنها الاختبار بالاسم:

  • context: fork — يشغّل المهارة في سياق فرعي معزول: المخرجات الطويلة (تحليل شامل للكود) أو الاستكشافية (عصف ذهني لبدائل) تبقى في الفرع، ويعود الملخص فقط إلى المحادثة الرئيسية فلا تتلوث.
  • allowed-tools — يقيّد الأدوات المتاحة أثناء تنفيذ المهارة: مثلاً السماح بعمليات الملفات فقط لمنع أي إجراء مدمّر. هذا مبدأ أقل صلاحية مطبقاً على المهارات.
  • argument-hint — لو استدعى المطوّر المهارة بدون وسيطها المطلوب، يظهر له التلميح ليعرف ما الذي يجب تمريره.

وتذكّر التخصيص الشخصي: لو أردت تعديل مهارة فريق لذوقك، أنشئ نسختك في ~/.claude/skills/ باسم مختلف — تعديل مهارة المشروع نفسها سيصل للجميع مع أول commit.

A skill goes beyond a command: a full folder in .claude/skills/ centered on a SKILL.md file whose frontmatter gives you three controls the exam asks about by name:

  • context: fork — runs the skill in an isolated sub-agent context: verbose output (a full codebase analysis) or exploratory context (brainstorming alternatives) stays in the fork, and only the summary returns to the main conversation, keeping it clean.
  • allowed-tools — restricts which tools are available during skill execution: e.g. file operations only, preventing any destructive action. Least privilege, applied to skills.
  • argument-hint — if a developer invokes the skill without its required argument, the hint prompts them for what to pass.

And remember personal customization: to tweak a team skill to your taste, create your variant in ~/.claude/skills/ under a different name — editing the project skill itself ships to everyone with the next commit.

مثال: .claude/skills/audit-deps/SKILL.mdExample: .claude/skills/audit-deps/SKILL.md
---
name: audit-deps
description: Audit dependencies for security and license issues
context: fork            # verbose scan stays in an isolated sub-agent
allowed-tools: Read, Grep, Glob    # read-only: no Bash, no destructive writes
argument-hint: [package-name]      # shown if invoked without an argument
---
Audit the dependency tree for `$ARGUMENTS`:

1. Find every place it is imported (Grep) and how it is used.
2. Flag known-vulnerable or unmaintained versions.
3. Return a SHORT summary table only — the full scan stays in the fork,
   so the main conversation is not flooded with hundreds of lines.

المسح الكامل يحدث في الفرع المعزول ويفنى فيه — المحادثة الرئيسية تستلم الملخص القصير فقط. The full scan happens and dies inside the isolated fork — the main conversation receives only the short summary.

نصيحةTip
اسأل عن كل مهارة سؤالين مستقلين: «هل مخرجاتها طويلة أو استكشافية؟» → context: fork. «هل يمكن أن تفعل شيئاً مدمّراً؟» → allowed-tools. حقلان مختلفان لمشكلتين مختلفتين — تلوّث السياق شيء، والصلاحيات شيء آخر.
Ask two independent questions of every skill: "Is its output long or exploratory?" → context: fork. "Could it do something destructive?" → allowed-tools. Two different fields for two different problems — context pollution is one thing, privileges another.

مهارة أم CLAUDE.md؟ Skill or CLAUDE.md?

القاعدة الفاصلة: المهارة تُستدعى عند الطلب لسير عمل خاص بمهمة (تدقيق تبعيات، توليد تقرير)، بينما CLAUDE.md يُحمَّل دائماً في كل جلسة للمعايير العامة الثابتة. الخطآن المتقابلان: تحويل معيار دائم إلى مهارة (لن تُطبَّق إلا لو تذكّر أحدهم استدعاءها)، وحشر سير عمل ثقيل نادر الاستخدام في CLAUDE.md (يستهلك سياق كل جلسة بلا داعٍ).

The dividing rule: skills are invoked on demand for task-specific workflows (dependency audit, report generation), while CLAUDE.md is always loaded in every session for universal standing standards. The two symmetric mistakes: turning an always-on standard into a skill (it only applies if someone remembers to invoke it), and cramming a heavy, rarely-used workflow into CLAUDE.md (burning every session's context for nothing).

مفهوم أساسيKey concept
context: fork يعزل السياق، وallowed-tools يقيّد الصلاحيات — لا يستبدل أحدهما الآخر أبداً. سؤال يطلب «منع الأوامر المدمّرة» جوابه allowed-tools حتى لو ظهر fork بين الخيارات بصياغة مغرية.
context: fork isolates context; allowed-tools restricts privileges — neither ever substitutes for the other. A question asking to "prevent destructive commands" is answered by allowed-tools, even when fork appears among the options in tempting wording.

فخ الاختبارExam trap

  • الفخ: أمر للفريق كله → وضعه في ~/.claude/commands/ أو داخل CLAUDE.md أو .claude/config.json بمصفوفة أوامر. الصح: .claude/commands/ داخل المستودع — والخيار الأخير آلية غير موجودة أصلاً.
    Trap: a team-wide command → placing it in ~/.claude/commands/, inside CLAUDE.md, or a .claude/config.json commands array. Reality: .claude/commands/ in the repository — and that last option is a mechanism that does not exist.
  • الفخ: استخدام context: fork «للأمان» ومنع الأوامر الخطرة. الصح: fork يعزل السياق فقط — الأمان والتقييد وظيفة allowed-tools.
    Trap: using context: fork "for safety" to block dangerous commands. Reality: fork only isolates context — safety and restriction are allowed-tools' job.
  • الفخ: تعديل مهارة المشروع مباشرة «لتجربة شخصية». الصح: نسخة شخصية في ~/.claude/skills/ باسم مختلف — التعديل المباشر يصل للجميع مع أول commit.
    Trap: editing the project skill directly "as a personal experiment." Reality: a personal variant in ~/.claude/skills/ with a different name — a direct edit reaches everyone on the next commit.

مثال من الحياة: الاستشاري في الغرفة الجانبيةReal-life example: the consultant in the side room

الأمر المخصّص مثل نموذج طلب جاهز في أدراج الشركة: بدل ما يكتب كل موظف الخطاب من الصفر، يسحب النموذج ويعبّي الفراغ ($ARGUMENTS). لو كان النموذج في الأرشيف المشترك استفاد منه الجميع، ولو في درجك الخاص فهو لك وحدك.

أما المهارة فهي استشاري تستدعيه لمهمة محددة: تجلسه في غرفة جانبية (context: fork) حتى لا يغرق طاولة الاجتماع الرئيسية بأكوام أوراقه — يدخل عليك بالخلاصة فقط. وقبل أن يبدأ، تسلّمه تصريح دخول محدود (allowed-tools): يقرأ الملفات لكنه لا يوقّع الشيكات. ولو حضر بدون ملف القضية، موظف الاستقبال يسأله عنه (argument-hint).

A custom command is a ready-made form in the company drawers: instead of every employee writing the letter from scratch, they pull the template and fill the blank ($ARGUMENTS). Kept in the shared archive, everyone benefits; kept in your own drawer, it is yours alone.

A skill is a consultant called in for a specific job: you seat them in a side room (context: fork) so they do not bury the main meeting table under their piles of paper — they walk in with only the summary. Before they start, you hand them a limited access badge (allowed-tools): they may read files but never sign checks. And if they arrive without the case file, the receptionist asks for it (argument-hint).

تحب مهارة الفريق generate-report لكنك تريد نسخة معدّلة بتنسيقك الخاص، دون أن يتأثر أي زميل. ما التصرف الصحيح؟ You like the team's generate-report skill but want a modified version with your own formatting, without affecting any teammate. What is the correct move?

صحيح. هذا النمط الرسمي للتخصيص الشخصي: نسخة في ~/.claude/skills/ باسم مختلف. تعديل ملف المشروع (A) يصل للجميع مع أول commit، وحشو CLAUDE.md بتفضيلات شخصية (C) يفرضها على الفريق، وfork (D) يعزل السياق ولا يجعل المهارة «شخصية».
Correct. This is the official personal-customization pattern: a variant in ~/.claude/skills/ under a different name. Editing the project file (A) ships to everyone on the next commit, stuffing personal preferences into CLAUDE.md (C) imposes them on the team, and fork (D) isolates context — it does not make a skill "personal."
الإجابة الصحيحة B. أي شيء داخل المستودع يصل للجميع — التخصيص الشخصي مكانه ~/.claude/skills/ وباسم مختلف تحديداً حتى لا يتعارض مع مهارة الفريق الأصلية.
The correct answer is B. Anything inside the repository reaches everyone — personal customization belongs in ~/.claude/skills/, specifically under a different name so it never conflicts with the original team skill.

مهارة brainstorm-alternatives تولّد صفحات من الأفكار والمقارنات الاستكشافية، ولاحظت أن بقايا هذا العصف تشوّش قرارات Claude في بقية الجلسة. أي حقل frontmatter يحل المشكلة؟ A brainstorm-alternatives skill generates pages of exploratory ideas and comparisons, and you notice the leftover brainstorm noise skewing Claude's decisions for the rest of the session. Which frontmatter field solves this?

صحيح. المشكلة هي تلوّث السياق بمخرجات استكشافية — وهذا هو الغرض المنصوص لـ context: fork: العصف كله يعيش في الفرع، والمحادثة الرئيسية تستلم الخلاصة فقط. تقييد الأدوات لا يقلل النثر الاستكشافي، والتلميح لا يغيّر مكان المخرجات، ونقل المهارة يغيّر من يملكها لا أين تتنفذ.
Correct. The problem is context pollution by exploratory output — the stated purpose of context: fork: the whole brainstorm lives in the fork, and the main conversation receives only the conclusion. Restricting tools does not reduce exploratory prose, a hint does not relocate output, and moving the skill changes who owns it, not where it executes.
الإجابة الصحيحة C. إشارات السؤال «مخرجات استكشافية/طويلة» و«تشوّش بقية الجلسة» تعني عزل سياق = context: fork. الدليل الرسمي يذكر تحليل الكود المطوّل والعصف الذهني كمثالين نموذجيين له.
The correct answer is C. The cues "exploratory/verbose output" and "skewing the rest of the session" mean context isolation = context: fork. The official guide names verbose codebase analysis and brainstorming as its two canonical examples.

المطوّرون يستدعون مهارة migrate-endpoint كثيراً بدون تمرير اسم الـ endpoint المطلوب، فتنفّذ على افتراضات خاطئة. ما أبسط ضبط يعالج هذا؟ Developers keep invoking the migrate-endpoint skill without passing the required endpoint name, so it runs on wrong assumptions. What is the simplest configuration fix?

صحيح. argument-hint مصمَّم لهذه الحالة حرفياً: يذكّر المطوّر بالمعطى المطلوب عند الاستدعاء بدون وسائط. الحلان A وD يستخدمان حقولاً لأغراض أخرى (عزل سياق / تقييد صلاحيات)، وC تعليمات احتمالية في ملف عام بدل ضبط حتمي في المهارة نفسها.
Correct. argument-hint is designed for literally this case: prompting the developer for the required parameter when invoking without arguments. A and D use fields built for other purposes (context isolation / privilege restriction), and C is probabilistic instruction in a global file instead of deterministic configuration on the skill itself.
الإجابة الصحيحة B. «استدعاء بدون المعطى المطلوب» هي الإشارة المعيارية لحقل argument-hint — كل حقل frontmatter له وظيفة واحدة محددة، والاختبار يحب من يعرف أيها لأي مشكلة.
The correct answer is B. "Invoked without the required parameter" is the canonical cue for argument-hint — each frontmatter field has one specific job, and the exam rewards knowing which solves which problem.
