القواعد الخاصة بالمسارات Path-specific rules

الاتفاقية الذكية تحضر وقت الحاجة فقط: نمط glob واحد يطارد الملف أينما كان — بدون حشو سياق كل جلسة. Smart conventions show up only when needed: one glob pattern follows the file wherever it lives — without stuffing every session's context.

وش بتتعلمWhat you'll learn

  • كتابة ملفات .claude/rules/ بترويسة YAML فيها حقل paths بأنماط glob (مثل paths: ["terraform/**/*"])Writing .claude/rules/ files with YAML frontmatter whose paths field holds glob patterns (e.g. paths: ["terraform/**/*"])
  • كيف تُحمَّل القاعدة فقط عند تحرير ملف مطابق — فيقل السياق غير ذي الصلة وتوفَّر الـ tokensHow a rule loads only when editing a matching file — cutting irrelevant context and saving tokens
  • تطبيق الاتفاقيات بحسب نوع الملف لا موقعه (**/*.test.tsx لكل ملفات الاختبار أينما كانت)Applying conventions by file type, not location (**/*.test.tsx for all test files wherever they live)
  • متى تختار قاعدة paths بدل CLAUDE.md المجلدي — ومتى يبقى المجلدي كافياًWhen to choose a paths rule over a directory CLAUDE.md — and when the directory file remains enough

كيف يعمل التفعيل الشرطي How conditional activation works

ملف القاعدة في .claude/rules/ يبدأ بترويسة YAML فيها حقل paths يحوي أنماط glob. الميكانيكية بسيطة وحتمية: عند تحرير ملف، يُقارن مساره بالأنماط — تطابق؟ تُحمَّل القاعدة. لا تطابق؟ لا تظهر في السياق إطلاقاً.

الفائدة مزدوجة: أولاً دقة التطبيق — اتفاقيات الاختبارات تحضر مع ملفات الاختبار فقط، فلا تتزاحم التعليمات غير ذات الصلة في كل جلسة. وثانياً اقتصاد السياق — كل قاعدة غير محمَّلة هي tokens موفَّرة تترك مساحة لما يهم فعلاً.

وقوة glob الحقيقية أنها تطابق بحسب النوع لا الموقع: النمط **/*.test.tsx يلتقط Button.test.tsx بجوار Button.tsx في أي مجلد من المستودع، والنمط terraform/**/* يغطي شجرة البنية التحتية كاملة بقاعدة واحدة.

A rule file in .claude/rules/ opens with YAML frontmatter whose paths field holds glob patterns. The mechanics are simple and deterministic: when a file is edited, its path is checked against the patterns — match? The rule loads. No match? It never enters context at all.

The benefit is double: first, precision — testing conventions arrive with test files only, so unrelated instructions stop crowding every session. Second, context economy — every unloaded rule is saved tokens, leaving room for what actually matters.

glob's real power is matching by type, not location: **/*.test.tsx catches Button.test.tsx sitting next to Button.tsx in any folder of the repo, and terraform/**/* covers the whole infrastructure tree with a single rule.

نفس المجلد، ملفان مختلفان: ملف الاختبار يفعّل القاعدة، وملف المكوّن لا يحمّلها أصلاً. Same folder, two files: the test file activates the rule; the component file never loads it.

مثال: .claude/rules/testing.md — اتفاقية بحسب النوعExample: .claude/rules/testing.md — a by-type convention
---
# Loads ONLY when the edited file matches, wherever it lives.
paths:
  - "**/*.test.tsx"
  - "**/*.test.ts"
  - "**/__tests__/**"
---
# Testing conventions

- Use React Testing Library; query by role/label, never by test-id.
- One `describe` block per component; colocate the test next to its source.
- Mock network calls with MSW handlers, never ad-hoc `fetch` stubs.
- Cover the empty, null, and boundary cases for every new branch.
مثال: .claude/rules/terraform.md — اتفاقية بحسب المنطقةExample: .claude/rules/terraform.md — a by-area convention
---
paths:
  - "terraform/**/*"
---
# Infrastructure conventions

- Every resource gets `environment` and `owner` tags.
- Never hardcode regions; use `var.region`.
- State changes require a plan file reviewed in the PR.
لمحة سريعةQuick insight
كلمتان في نص السؤال تكشفان الإجابة: «تلقائياً» (تستبعد المهارات لأنها تُستدعى يدوياً) و«منتشرة عبر المستودع» (تستبعد CLAUDE.md المجلدي لأنه مقيّد بموقعه). ما يبقى: قاعدة paths.
Two words in the question give the answer away: "automatically" (eliminates skills — manually invoked) and "spread across the repo" (eliminates a directory CLAUDE.md — location-bound). What remains: a paths rule.

قاعدة paths أم CLAUDE.md مجلدي؟ A paths rule or a directory CLAUDE.md?

القاعدة الفاصلة: الاتفاقية التي تتبع نوع الملف (اختبارات، ترحيلات، ملفات إعداد) منتشرة بطبيعتها عبر المجلدات — تحتاج قاعدة glob واحدة تطاردها أينما كانت. أما الاتفاقية المرتبطة بمنطقة متماسكة واحدة (كل frontend/ مثلاً) فيكفيها CLAUDE.md داخل ذلك المجلد — وهو خيار مشروع تماماً هناك.

حاول تغطية ملفات منتشرة بملفات CLAUDE.md مجلدية وستنتهي بعشرات النسخ المكررة التي تنحرف عن بعضها مع كل تعديل. هذا بالضبط السيناريو الذي صُمم له حقل paths.

The dividing rule: a convention that follows a file type (tests, migrations, config files) is inherently spread across directories — it needs one glob rule chasing it wherever it goes. A convention tied to one cohesive area (all of frontend/, say) is well served by a CLAUDE.md inside that folder — a perfectly legitimate choice there.

Try covering spread-out files with directory CLAUDE.md copies and you end up with dozens of duplicates drifting apart on every edit. That is exactly the scenario the paths field was designed for.

مفهوم أساسيKey concept
أنماط glob مطابقة صريحة وحتمية؛ الاعتماد على Claude «يستنتج» القسم المناسب من عناوين ملف موحّد مطابقة احتمالية. حين يطلب السؤال ضماناً تلقائياً بحسب المسار، الحتمي يفوز دائماً.
glob patterns are explicit, deterministic matching; relying on Claude to "infer" the right section from a consolidated file's headers is probabilistic. When a question demands automatic, path-based application, deterministic always wins.

فخ الاختبارExam trap

  • الفخ: «وحّد كل الاتفاقيات في CLAUDE.md الجذر تحت عناوين، ودع Claude يستنتج القسم المناسب». الصح: الاستنتاج احتمالي وغير موثوق — المطابقة الصريحة بـ glob حتمية.
    Trap: "consolidate all conventions in the root CLAUDE.md under headers and let Claude infer the right section." Reality: inference is probabilistic and unreliable — explicit glob matching is deterministic.
  • الفخ: «أنشئ مهارة لكل نوع كود تحمل اتفاقياته في SKILL.md». الصح: المهارات تُستدعى يدوياً — يناقض شرط التطبيق «التلقائي» بحسب المسار.
    Trap: "create a skill per code type carrying its conventions in SKILL.md." Reality: skills are manually invoked — contradicting the "automatic" path-based requirement.
  • الفخ: «ضع CLAUDE.md في كل مجلد فرعي فيه ملف اختبار». الصح: نسخ مكررة تنحرف مع الوقت — لملفات منتشرة، قاعدة glob واحدة هي مصدر الحقيقة.
    Trap: "put a CLAUDE.md in every subdirectory containing a test file." Reality: duplicated copies drift over time — for spread files, one glob rule is the single source of truth.

مثال من الحياة: أمن المطارReal-life example: airport security

قاعدة أمن المطار «كل من يحمل سوائل يمر بفحص إضافي» تنطبق بحسب ما تحمله، لا بحسب البوابة التي دخلت منها — مسافر البوابة 3 ومسافر البوابة 47 يخضعان لنفس القاعدة تلقائياً. هذه هي قاعدة paths بنمط glob: تلتقط **/*.test.tsx في أي مجلد.

البديل الساذج؟ لوحة تعليمات منفصلة عند كل بوابة من الأربعين (نسخة CLAUDE.md في كل مجلد) — وستُحدَّث لوحة وتُنسى أخرى حتى تتناقض اللوحات. أما لوحة «تعليمات صالة كبار الزوار» المعلّقة داخل الصالة نفسها فمناسبة تماماً — لأنها تخص منطقة واحدة متماسكة، مثل CLAUDE.md داخل frontend/.

The airport rule "anyone carrying liquids goes through extra screening" applies by what you carry, not which gate you entered — the traveler at gate 3 and the one at gate 47 hit the same rule automatically. That is a paths rule with a glob: it catches **/*.test.tsx in any folder.

The naive alternative? A separate instruction board at each of the forty gates (a CLAUDE.md copy per directory) — one board gets updated, another forgotten, until they contradict each other. But the "VIP lounge rules" board hanging inside the lounge itself is perfectly fine — it governs one cohesive area, like a CLAUDE.md inside frontend/.

في الاختبارOn the exam

كيف يجي السؤالHow it is asked
  • السؤال الرسمي النموذجي: مناطق كود بأنماط مختلفة + ملفات اختبار منتشرة بجوار مصادرها + مطلوب تطبيق «تلقائي» — الجواب قاعدة rules بـ glob.The canonical official question: code areas with different styles + test files colocated everywhere + "automatic" application required — answered by a rules file with a glob.
  • صيغة «تقليل السياق غير ذي الصلة / توفير tokens» — ميزة التحميل الشرطي لقواعد paths.The "reduce irrelevant context / save tokens" phrasing — the conditional-loading advantage of paths rules.
  • قد يعكسون السؤال: منطقة واحدة متماسكة فقط — عندها CLAUDE.md المجلدي إجابة صحيحة مشروعة.They may invert it: one cohesive area only — where a directory CLAUDE.md is a legitimate correct answer.
إجابات فخ تستبعدها فوراًTrap answers to eliminate
  • «عناوين في ملف موحّد ويستنتج Claude» — احتمالي حيث يُطلب الحتمي."Headers in one consolidated file, Claude infers" — probabilistic where determinism is demanded.
  • «مهارة لكل نوع كود» — استدعاء يدوي يناقض «تلقائياً»."A skill per code type" — manual invocation contradicting "automatically."
  • «نسخة CLAUDE.md في كل مجلد» لملفات منتشرة — عبء نسخ ينحرف."A CLAUDE.md copy per directory" for spread files — a drifting duplication burden.

فريق البنية التحتية يريد اتفاقيات Terraform (وسوم إلزامية، منع كتابة الـ region يدوياً) أن تُحمَّل فقط عند تحرير ملفات داخل شجرة terraform/ — لا في جلسات الواجهة ولا الـ API. كيف تحقق ذلك؟ The infrastructure team wants Terraform conventions (mandatory tags, no hardcoded regions) loaded only when editing files inside the terraform/ tree — never in frontend or API sessions. How do you achieve that?

صحيح. هذا المثال الحرفي من الدليل الرسمي: قاعدة paths: ["terraform/**/*"] تُحمَّل فقط عند تحرير ملف مطابق. الخيار A يحمّلها في كل جلسة (عكس المطلوب)، وC استدعاء يدوي يُنسى، وD شخصي لا يُشارك ولا يضمن الاتساق.
Correct. This is the guide's literal example: a paths: ["terraform/**/*"] rule loads only when a matching file is edited. Option A loads it in every session (the opposite of the requirement), C is a forgettable manual invocation, and D is personal, unshared, and inconsistent.
الإجابة الصحيحة B. المطلوب تحميل شرطي بحسب المسار — وهذه وظيفة حقل paths في ملفات .claude/rules/ تحديداً. الملف الجذري دائم التحميل، والمهارة يدوية، والملف الشخصي لا يُشارَك.
The correct answer is B. The requirement is conditional, path-based loading — precisely the job of the paths field in .claude/rules/ files. The root file always loads, a skill is manual, and the personal file is unshared.

متى تتفوّق قاعدة glob في .claude/rules/ بوضوح على ملف CLAUDE.md مجلدي؟ When does a glob rule in .claude/rules/ clearly beat a directory-level CLAUDE.md?

صحيح. الميزة الحاسمة لأنماط glob: تطارد نوع الملف عبر حدود المجلدات (**/*.test.tsx)، بينما CLAUDE.md المجلدي أسير مجلده. في A الخياران متكافئان تقريباً، وB عكس فكرة التحميل الشرطي، وD وظيفة allowed-tools في المهارات لا القواعد.
Correct. The decisive advantage of glob patterns: they chase a file type across directory boundaries (**/*.test.tsx), while a directory CLAUDE.md is captive to its folder. In A the two options are roughly equivalent, B is the opposite of conditional loading, and D is the job of allowed-tools on skills, not rules.
الإجابة الصحيحة C. الدليل الرسمي ينص على الميزة حرفياً: قواعد glob تتفوّق على CLAUDE.md المجلدي «للاتفاقيات الممتدة عبر مجلدات متعددة» مثل ملفات الاختبار المنتشرة في المستودع.
The correct answer is C. The official guide states the advantage verbatim: glob rules beat directory CLAUDE.md files "for conventions that span multiple directories," like test files scattered through a codebase.

اتفاقيات تصميم مكونات React عندكم تخص مجلد frontend/ وحده — كل ملفاته هناك ولا يوجد كود واجهة في أي مكان آخر. أي خيار بسيط ومناسب تماماً هنا؟ Your React component design conventions concern the frontend/ folder alone — all its files live there and no UI code exists anywhere else. Which simple option fits perfectly here?

صحيح. الحكم الصحيح يعمل بالاتجاهين: منطقة واحدة متماسكة → CLAUDE.md مجلدي حل بسيط ومشروع (وقاعدة glob بنمط frontend/**/* تعمل أيضاً — لكن المجلدي ليس خطأ هنا). الفخ هو الاعتقاد أن قواعد glob «الإجابة الصحيحة دائماً» بلا نظر للسيناريو.
Correct. Good judgment cuts both ways: one cohesive area → a directory CLAUDE.md is a simple, legitimate solution (a glob rule with frontend/**/* works too — but the directory file is not wrong here). The trap is believing glob rules are "always the right answer" regardless of scenario.
الإجابة الصحيحة A. قاعدة glob تتفوّق للملفات المنتشرة؛ أما منطقة واحدة متماسكة فملف CLAUDE.md داخلها مناسب تماماً. لا تحفظ «قواعد glob دائماً» — احفظ لماذا تتفوّق ومتى.
The correct answer is A. A glob rule wins for spread files; for one cohesive area, a CLAUDE.md inside it fits perfectly. Do not memorize "glob rules always" — remember why they win and when.
