5.3

انتشار الأخطاء في الأنظمة متعددة الوكلاء Error propagation across multi-agent systems

ليش مهم؟ لأن الوكيل اللي يفشل بصمت أخطر من اللي يفشل بصوت عالٍ — التقرير الناقص اللي «يبدو كاملًا» ما أحد يشك فيه. Why it matters: an agent that fails silently is more dangerous than one that fails loudly — nobody doubts an incomplete report that "looks complete."

1 سياق الخطأ المنظّم — مدخل قرار، لا سطر log Structured error context — a decision input, not a log line

لما يفشل وكيل فرعي (بحث الويب صار عليه timeout مثلًا)، الطريقة اللي ينتقل بها الفشل للمنسّق تحدد مصير النظام كله: يتعافى بذكاء، أو ينتج تقريرًا ناقصًا، أو ينهار بلا داعٍ. القاعدة الذهبية: أرجِع سياق خطأ منظّمًا يتضمن أربعة عناصر:

  • نوع الفشل (failure_type): فشل وصول؟ عابر؟ قابل للإعادة؟
  • الاستعلام المُحاوَل: وش كان الوكيل يحاول بالضبط لحظة الفشل.
  • النتائج الجزئية: وش انحفظ قبل الفشل — قد تكفي للمتابعة.
  • البدائل الممكنة: اقتراحات ملموسة (استعلام أضيق، مصدر بديل، متابعة مع توثيق الفجوة).

بهذي الأربعة، المنسّق يقدر يقرر بذكاء: يعيد المحاولة باستعلام معدَّل؟ يجرب نهجًا بديلًا؟ أو يمشي بالنتائج الجزئية ويوثّق الفجوة؟ بدونها، قراره تخمين.

When a subagent fails (say the web search hits a timeout), how the failure travels to the coordinator decides the whole system's fate: recover intelligently, produce an incomplete report, or collapse needlessly. The golden rule: return structured error context with four elements:

  • Failure type (failure_type): access failure? transient? retryable?
  • Attempted query: exactly what the agent was trying at the moment of failure.
  • Partial results: what was captured before the failure — it may be enough to proceed.
  • Potential alternatives: concrete suggestions (a narrower query, an alternative source, proceeding while documenting the gap).

With these four, the coordinator can decide intelligently: retry with a modified query? try an alternative approach? or proceed with partial results and annotate the gap? Without them, its decision is a guess.

مثال — سياق خطأ منظّم من وكيل فرعي فاشلExample — structured error context from a failed subagent

  ],
  "alternatives": [

    "delegate to document_analysis agent over the local corpus",
    "proceed and annotate 'film' as a COVERAGE GAP in synthesis"

مفهوم أساسيKey concept

الخطأ في نظام متعدد الوكلاء مدخل قرار للمنسّق، مو مجرد سطر في السجل. قيمته تُقاس بسؤال واحد: هل يمكّن المنسّق من اختيار أفضل مسار تعافٍ؟ «البحث غير متاح» لا يمكّنه — والـ JSON المنظّم أعلاه يمكّنه. In a multi-agent system, an error is a decision input for the coordinator, not just a log line. Its value is measured by one question: does it let the coordinator pick the best recovery path? "Search unavailable" doesn't — the structured JSON above does.

2 فشل الوصول لا يساوي «نتيجة فارغة صحيحة» An access failure is not a "valid empty result"

أخطر خلط في هذا الموضوع: التعامل مع «ما قدرت أوصل للمصدر» كأنها «بحثت وما لقيت شيئًا». الأولى فشل وصول (access failure) — المصدر ما انفحص أصلًا، والسؤال المفتوح: نعيد المحاولة؟ الثانية نتيجة فارغة صحيحة — استعلام نجح فعلًا ولم يجد تطابقات، وهذي معلومة مكتملة يبني عليها المنسّق.

الخلط بينهما يعني: فجوة تغطية حقيقية تتنكّر في هيئة «لا توجد بيانات»، فيكتب التقرير خلاصات عن مجال ما فُحص إطلاقًا. لذلك تقرير الخطأ لازم يفرّق بين الحالتين صراحةً — حقل failure_type موجود لهذا السبب بالذات.

The most dangerous conflation in this topic: treating "I couldn't reach the source" as "I searched and found nothing." The first is an access failure — the source was never actually examined, and the open question is: should we retry? The second is a valid empty result — a query that genuinely succeeded and found no matches, which is complete information the coordinator can build on.

Conflating them means a real coverage gap masquerades as "no data exists," and the report draws conclusions about an area that was never examined at all. That's why error reporting must explicitly distinguish the two cases — the failure_type field exists for exactly this reason.

ACCESS FAILURE

"failure_type": "access_failure"

"error": "timeout after 30s"

"is_retryable": true

source was NEVER examined

  • open question: retry? alternative source?
  • if unresolved: a COVERAGE GAP in the report

VALID EMPTY RESULT

"status": "success"

"results": []

"query_completed": true

source WAS examined — no matches

  • complete information: nothing exists there
  • coordinator can safely build on it

شكلهما متقارب في الكود («لا نتائج») لكن معناهما متضاد: الأول سؤال معلّق، والثاني جواب مكتمل. They look similar in code ("no results") but mean opposite things: the first is an open question, the second a complete answer.

لمحة سريعةQuick insight

اسأل دائمًا: «هل المصدر انفحص فعلًا؟». انفحص وما فيه شيء = فارغ صحيح. ما انفحص = فشل وصول. سؤال واحد يفكّ أعقد أسئلة 5.3. Always ask: "was the source actually examined?" Examined and empty = valid empty. Never examined = access failure. One question untangles the hardest 5.3 items.

3 الأنماط المضادة الثلاثة — وتعليقات التغطية The three anti-patterns — and coverage annotations

ثلاثة أنماط تتكرر كمموِّهات في السؤال الرسمي عن الـ timeout، وكلها خاطئة لنفس السبب: تحرم المنسّق من سياق القرار:

  • الحالة العامة: إعادة محاولة داخلية بـ backoff ثم إرجاع «البحث غير متاح» — الإعادة المحلية ممتازة، لكن الحالة العامة بعدها تخفي كل السياق القيّم (وش جُرِّب؟ وش انحفظ؟ وش البدائل؟).
  • الإخماد الصامت: التقاط الـ timeout وإرجاع مجموعة فارغة «ناجحة» — يحوّل الفشل لنجاح، يمنع أي تعافٍ، وينتج بحثًا ناقصًا يبدو كاملًا.
  • الإنهاء الشامل: تمرير الاستثناء لمعالج علوي يقتل كامل سير البحث — إنهاء بلا داعٍ بينما استراتيجيات التعافي كانت ستنجح.

والصورة الكاملة الصحيحة: تعافٍ محلي للأخطاء العابرة داخل الوكيل الفرعي (إعادة محدودة، انتظار قصير)، وتصعيد منظّم لما يعجز عنه — ثم في النهاية، تعليقات تغطية في مخرَج التجميع: «مدعوم جيدًا: الفنون البصرية والموسيقى | فجوة: إنتاج الأفلام (المصدر غير متاح)». التقرير الصادق يعلن حدوده.

Three patterns recur as distractors in the official timeout question, all wrong for the same reason: they starve the coordinator of decision context:

  • The generic status: internal retries with backoff, then returning "search unavailable" — the local retries are great, but the generic status afterward hides all the valuable context (what was attempted? what was captured? what alternatives exist?).
  • Silent suppression: catching the timeout and returning an empty set marked successful — turns failure into success, prevents any recovery, and yields incomplete research that looks complete.
  • Total termination: propagating the exception to a top-level handler that kills the whole research workflow — unnecessary when recovery strategies could have succeeded.

The complete correct picture: local recovery for transient errors inside the subagent (bounded retries, short waits), structured propagation of what it can't resolve — and finally, coverage annotations in the synthesis output: "Well-supported: visual arts, music | Gap: film production (source unavailable)." An honest report declares its limits.

نصيحة: التغطية جزء من المخرَجTip: coverage is part of the output

تقرير التجميع الجيد ما يدّعي الكمال. لو مصدر «الأفلام» فشل، يقول صراحةً: «مغطّى جيدًا: الفنون البصرية والموسيقى | فجوة: إنتاج الأفلام (المصدر غير متاح)». هكذا يعرف المنسّق والقارئ حدود الثقة بدل ما ينخدعوا بتقرير أملس. A good synthesis report doesn't claim completeness. If the "film" source failed, it states plainly: "Well-supported: visual arts, music | Gap: film production (source unavailable)." The coordinator and the reader then know the limits of confidence instead of being fooled by a smooth report.

فخ الاختبارExam trap

  • «إعادة تلقائية بـ exponential backoff ثم حالة عامة» — نصفها الأول صحيح (تعافٍ محلي) لكن الحالة العامة في النهاية تخفي السياق؛ لذلك الخيار كله خاطئ. انتبه للمموِّهات «نصف الصحيحة»."Automatic retry with exponential backoff, then a generic status" — the first half is right (local recovery) but the generic status at the end hides context, so the whole option is wrong. Watch for "half-correct" distractors.

  • «التقط الـ timeout وأرجِع فارغًا ناجحًا» — إخماد صامت: يمنع التعافي وينتج مخرجات ناقصة تبدو كاملة."Catch the timeout and return an empty success" — silent suppression: blocks recovery and produces incomplete outputs that look complete.

  • «مرّر الاستثناء لمعالج يُنهي كل شيء» — إنهاء زائد عن الحاجة بينما التعافي الجزئي ممكن."Propagate the exception to a handler that terminates everything" — unnecessary termination when partial recovery was possible.

مثال من الحياة: مطبخ المطعم وقت الذروةReal-life example: a restaurant kitchen at rush hour

طباخ القسم (الوكيل الفرعي) اكتشف أن السلمون خلص في منتصف الذروة. الطباخ الشاطر يحاول أولًا محليًا: يفحص الثلاجة الثانية، يسأل المخزن (إعادة محاولة محدودة). فشلت؟ يبلّغ الشيف التنفيذي (المنسّق) بتقرير كامل: «السلمون خلص، فحصت الثلاجتين، عندي 6 صحون جاهزة من طلبية سابقة، وأقدر أستبدله بالهامور أو نشيل الطبق من القائمة الليلة» — نوع الفشل، وش جُرِّب، النتائج الجزئية، والبدائل.

الكوارث الثلاث المقابلة: يقول «المطبخ فيه مشكلة» بس (حالة عامة)؛ أو يطلع صحون سلمون ناقصة وكأن شيئًا لم يكن (فارغ-كنجاح)؛ أو يقفل المطبخ كله على أساس مكوّن واحد (إنهاء شامل). وفي آخر الليل، تقرير الشيف الصادق يقول: «كل الأطباق طلعت كاملة إلا السلمون — شلناه الساعة 9» — هذي تعليقات التغطية.

A station cook (the subagent) discovers the salmon ran out mid-rush. A good cook tries locally first: checks the second fridge, asks the storeroom (bounded retries). Still nothing? He reports to the executive chef (the coordinator) with full context: "Salmon is out; I checked both fridges; I have 6 plated portions from the earlier batch; I can substitute grouper, or we pull the dish tonight" — failure type, what was attempted, partial results, alternatives.

The three matching disasters: saying only "the kitchen has a problem" (generic status); sending out incomplete salmon plates as if nothing happened (empty-as-success); or shutting down the entire kitchen over one ingredient (total termination). And at close, the honest chef's report reads: "All dishes went out complete except salmon — pulled at 9 pm" — that's a coverage annotation.

في الاختبارOn the exam

سؤال رسمي كامل هنا: «وكيل البحث صار عليه timeout — أي نهج انتشار خطأ يمكّن التعافي الذكي؟» والإجابة: سياق منظّم (نوع الفشل + الاستعلام المُحاوَل + النتائج الجزئية + البدائل). المموِّهات الثلاثة كانت حرفيًا: الحالة العامة، والفارغ-كنجاح، والإنهاء الشامل.

A full official question lives here: "the web search subagent times out — which error propagation approach best enables intelligent recovery?" Answer: structured context (failure type + attempted query + partial results + alternatives). The three distractors were literally: the generic status, empty-as-success, and total termination.

مموِّهات تشيلها فورًا:Distractors to eliminate on sight:

أي خيار ينتهي بحالة عامة تخفي التفاصيل — حتى لو بدايته (إعادة محلية) صحيحة.Any option ending in a generic status that hides details — even if its start (local retries) is right.

أي خيار يعلّم الفشل كنجاح («أرجِع فارغًا وامشِ»).Any option marking failure as success ("return empty and move on").

أي خيار يقتل سير العمل كله على فشل واحد قابل للتعافي.Any option killing the whole workflow over one recoverable failure.
